# qa-ai.config.yaml schema

Keys generated by `init` from presets in [`.qa-ai/presets/`](../../.qa-ai/presets/). The machine-readable source of
truth is [`.qa-ai/contracts/config.v1.schema.json`](../../.qa-ai/contracts/config.v1.schema.json). Versioned schema
surfaces, compatibility fixtures and unsupported-version behavior are documented in
[schema-compatibility.md](schema-compatibility.md). Values shown are typical defaults; presets override paths and tool
names. Presets may keep `CHANGE_ME` as an internal sentinel, but generated config files must not contain it. `init`
derives supported values such as `project.name` and `testrail.projectName`, and fails with the unresolved key paths
when any sentinel remains.

## Config file location

New projects use compact layout:

```text
.qa-ai/qa-ai.config.yaml
```

Resolution order:

1. `qa-ai.config.yaml` in the repository root (legacy; takes precedence when both exist)
2. `.qa-ai/qa-ai.config.yaml` when no root config exists

`doctor` warns (non-blocking) when both files exist. Custom paths in config always win over defaults.

| Key                                  | Type    | Description                                                 |
| ------------------------------------ | ------- | ----------------------------------------------------------- |

Legacy migration:

| Legacy pair                                                                           | New value                                      |
| ------------------------------------------------------------------------------------- | ---------------------------------------------- |
| `allowInferredAcceptanceCriteria: false`                                              | `inferredAcceptanceCriteria: forbid`           |

When both legacy keys and `inferredAcceptanceCriteria` are present, they must agree or `doctor` fails.

## `testDesign` / `traceability` / `approval` / `testManagementSync` / `commands`

| Section                                                  | Purpose                                                              |
| -------------------------------------------------------- | -------------------------------------------------------------------- |
| `testDesign.systemPath`                                  | System test design artifact                                          |
| `testDesign.proposalPath`                                | Per-RF proposal artifact                                             |
| `testDesign.coverage.mode`                               | `off`, `advisory` or `strict` coverage validation                    |
| `testDesign.coverage.requirePositive`                    | Require positive coverage per RF                                     |
| `testDesign.coverage.requireNegative`                    | Require negative coverage per RF                                     |
| `testDesign.coverage.requireAlternative`                 | Require an alternative flow or exclusion rationale                   |
| `testDesign.coverage.requireBoundaryWhenApplicable`      | Require BVA evidence when applicable                                 |
| `testDesign.coverage.requireAccessibilityWhenApplicable` | Require accessibility evidence or rationale                          |
| `testDesign.coverage.requirePerformanceWhenApplicable`   | Require performance evidence or rationale                            |
| `testDesign.coverage.requireSecurityReview`              | Require functional security applicability review                     |
| `testDesign.coverage.requireTechniqueTraceability`       | Require recorded test-design techniques                              |
| `testDesign.coverage.requireCriterionCoverage`           | Enforce atomic criterion proposal-to-feature gates                   |
| `testDesign.quality.mode`                                | `off`, `advisory` or `gate` semantic rubric review                   |
| `testDesign.quality.reportPath`                          | Gherkin quality report artifact                                      |
| `testDesign.quality.minDimensionsPassed`                 | Minimum passing rubric dimensions for gate mode                      |
| `testDesign.nonFunctionalCoverage.mode`                  | `inherit`, `advisory`, `strict` or `off` for source NFR policy       |
| `testDesign.strategyRouting.mode`                        | `off`, `advisory` or `strict` specialist keyword routing             |
| `testDesign.strategyRouting.includeKeywordSignals`       | Enable RF/CA keyword routing (default `true` when mode is not `off`) |
| `testDesign.strategyRouting.maxSpecialistsPerCriterion`  | Cap routed specialists per criterion (default `5`)                   |
| `testDesign.strategyRouting.criticalSignals`             | Strict-only keyword signals that require routing decision rows       |
| `traceability.matrixPath`                                | Traceability matrix                                                  |
| `approval.*`                                             | Gates before external writes / PR                                    |
| `testManagementSync.mode`                                | `proposal-only` or `governed`                                        |
| `testManagementSync.diffPath`                            | Governed sync diff artifact                                          |
| `testManagementSync.applyLogPath`                        | Governed sync apply log                                              |
| `testManagementSync.rollbackPath`                        | Governed sync rollback plan                                          |
| `testManagementSync.remoteSnapshotPath`                  | Governed sync remote-state snapshot                                  |
| `commands.testQA`                                        | Default validate-features command                                    |

`testManagementSync.mode` defaults to `proposal-only`, which preserves the local proposal-first workflow and performs
no external writes. `governed` adds the sync-diff, sync-apply and sync-verify harness phases; `sync-apply` is the only
phase allowed to request the `external-write:test-management` gate.

`testDesign.quality.mode` defaults to `off` in every preset. `advisory` writes a reviewable semantic Gherkin quality
report without blocking the workflow. `gate` treats the configured rubric threshold as a completion gate. See
[quality-rubric.md](quality-rubric.md).

`testDesign.strategyRouting.mode` defaults to `off` in code for backward compatibility. Standard presets (`playwright-full`, `karate-full`, `maestro-karate-mobile`, `selenium-jest-browserstack`, `webdriverio-playwright-api`) ship with `advisory`, which recommends specialists from keyword signals without blocking validators. `manual-only` ships with `off`. `strict` requires `## Strategy routing decisions` rows for signals listed in `testDesign.strategyRouting.criticalSignals` (defaults: `gdpr`, `browserstack`, `openapi`, `sast`, `dast`). Set `criticalSignals: []` to skip critical-signal row enforcement in strict mode.

```yaml
testDesign:
  strategyRouting:
    mode: advisory
    includeKeywordSignals: true
    maxSpecialistsPerCriterion: 5
    criticalSignals:
      - gdpr
      - browserstack
      - openapi
      - sast
      - dast
      - figma
      - biometric
```

## `validators` (experimental)

Custom validators are repo-local Node.js scripts declared under `validators.custom`. They run after built-in phase
validators in the harness and are also included in `validate-target --json`.

```yaml
validators:
  custom:
    - id: naming-check
      script: qa-custom/validate-naming.example.mjs
      phases:
        - gherkin
      blocking: false
```

| Key        | Type     | Description                                                                      |
| ---------- | -------- | -------------------------------------------------------------------------------- |
| `id`       | string   | Unique kebab-case id matching `^[a-z][a-z0-9-]{2,40}$`; cannot shadow built-ins  |
| `script`   | string   | Repo-relative Node.js script path; absolute paths and path traversal fail doctor |
| `phases`   | string[] | Workflow phase ids where the validator runs                                      |
| `blocking` | boolean  | Defaults to `true`; `false` records warnings without blocking phase completion   |

Scripts must support `--self-test --json` for `doctor` and should support `--json` for normal execution. JSON output
uses `{ "ok": boolean, "findings": [{ "file": "...", "line": 1, "message": "...", "severity": "error" }] }`.
`init --with-doc-templates` writes an example to `qa-custom/validate-naming.example.mjs`.

| Key                  | Type     | Description                                                                                 |

| `enabled`            | boolean  | Enable AI-component classification and technique traceability enforcement (default `false`) |

## YAML Syntax Restrictions

The configuration and release-gate files are processed by a strict, dependency-free YAML parser designed to prevent complex YAML features that complicate static analysis or security audits.

### Supported Features

- **Nested Structures**: Indented maps and sequences (including lists of mappings).
- **Comments**: Full-line and inline comments (e.g. `key: value # comment`).
- **Quoted Strings**: Double-quoted (`"..."`) and single-quoted (`'...'`) scalars with support for standard escape sequences.
- **Block Scalars**: Both literal (`|`) and folded (`>`) block scalars with default chomping.

### Unsupported Features (Triggers Located Error)

- **Tabs**: Tab characters (`\t`) are strictly forbidden for indentation.
- **Anchors & Aliases**: Use of `&anchor` or `*alias` raises an error.
- **Tags**: Schema tags (e.g., `!!str`) are rejected.
- **Flow Style Mappings**: Flow maps (e.g., `{key: value}`) and flow lists nested beyond simple inline lists (e.g., `[[nested]]`) are rejected.
