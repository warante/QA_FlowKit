Why QA FlowKit

AI agents can generate tests quickly, but QA teams still need structure, traceability, approval points and reproducible validation. QA FlowKit is 100% oriented to QA workflow — not app scaffolding or generic coding prompts.

1

The problem

Ad hoc prompts produce inconsistent Gherkin, lost RF links and CI with no clear contract for what “done” means in QA.

2

The approach

A repository-native QA harness: phased workflows, explicit approvals and deterministic validators — not prompt discipline alone.

3

For QA workflows

From requirement intake through Gherkin, traceability matrix, automation plan and release evidence — every step has defined outputs.

4

Clear boundaries

No bundled AI model, no telemetry, no silent external writes. Artifacts stay local and auditable inside the repository.

Without a QA harness

  • One-off prompts with no phase order
  • Inconsistent .feature files and missing tags
  • RF and acceptance criteria lost across sessions
  • CI has no shared quality gate for QA artifacts

With QA FlowKit

  • /qa-help recommends the next workflow step
  • validate-target runs the full repository quality gate
  • run start | next | check resumes work across agent sessions
  • Proposal-first synchronization plans — no silent test-management writes

AI agent

Reasons about requirements, drafts Gherkin, proposes synchronization plans and automation — edits files in the repository.

QA FlowKit harness

Validates outputs, blocks invalid phases, records approvals and keeps resumable run state under .qa-ai/state/.

Key control gates include official RF ID confirmation, proposal-first test-management synchronization and deterministic Gherkin validation before traceability and release decisions.

When you install QA FlowKit, you choose how much of the QA journey it guides. Both options keep tests, traceability and validators inside your repository.

Quick — Manual QA teams: requirements → Gherkin → traceability matrix (strategy routing off) Standard — Full workflow with advisory specialist routing from requirement signals

What it installs

A portable QA harness for QA repositories

QA FlowKit adds the framework folder, target repository configuration, generated artifacts, Gherkin files and optional agent adapters directly inside the repository under test.

Traceable test design

Validate RF links, duplicate IDs, coverage obligations and acceptance-criteria blocks.

Deterministic validators

Check Gherkin language, required tags, synchronization plans, release gates and generated QA artifacts.

Right-sized workflow

Start lean for manual QA or use the full path when you plan automation. Teams with audit needs can add an optional formal release checklist later.

Resumable harness

Persistent run state, append-only event log and run status across agent sessions.

On-demand specialist routing

Route privacy, mobile, security, cloud and other strategy specialists from requirement signals. Standard presets use advisory mode; strict mode can enforce documented routing decisions.

Safety boundaries

Keep outputs local, reject unsafe paths, scan untrusted content and avoid external writes in the MVP.

Command surface

CLI and agent commands

Run initial setup and validation from the terminal. Drive the QA flow from your AI coding tool with generated slash commands.

In your AI agent

Slash commands generated under .claude/commands/ or .opencode/commands/ after init. Each card links to its command definition in the framework.

/qa-help

Context-aware guidance — what to do next in the QA flow.
/qa-init

Guided QA FlowKit initialization inside the agent session.
/qa-config

Import or export reusable qa-ai.config.yaml profiles.
/qa-full-flow

Run the full guided QA FlowKit flow from start to finish.
/qa-add-tests

Add QA tests for a new requirement (RF).
/qa-update-tests

Review and apply approved updates to existing tests after RF changes.
/qa-automation-plan

Classify existing .feature files and plan automation backlog.
/qa-coverage

Analyze functional coverage across RFs, manual tests and automated tests.
/qa-impact

Propose affected tests from a branch, commit, PR or change reference.
/qa-quality

Evaluate Gherkin quality for an RF or feature path.
/qa-status

Summarize config, artifacts, feature health and recommended next steps.
/qa-doctor

Run setup health checks for the framework and target repository.
/qa-clean

Preview or execute manifest-based cleanup of generated files.
/qa-validate-features

Validate QA design Gherkin files against framework rules.
/qa-validate-karate-features

Validate executable Karate features against framework rules.
/qa-enable-enterprise

Optional: formal release checklist and stricter validation for audit-sensitive teams.
/qa-gate

Record a documented go/no-go decision when using the optional release checklist.

In your terminal

npx qa-flowkit

Copy .qa-ai/ into the repository. Then configure with /qa-init or node .qa-ai/scripts/init.mjs.

npx qa-flowkit doctor

Installation health check for the framework and target repository configuration.

npx qa-flowkit help

Recommend the next QA flow step based on current artifacts.

npx qa-flowkit run start | next | check

Resumable harness with per-phase validation and approval gates.

npx qa-flowkit validate-target

Run the full target-repository quality gate (strict doctor + validators).

npx qa-flowkit export-report

Export Gherkin-aligned test cases to Cucumber JSON, Allure or JUnit XML.
