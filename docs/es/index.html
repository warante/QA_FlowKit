Hecho por y para equipos QA

Por qué QA FlowKit

Los agentes de IA pueden generar pruebas rápido, pero los equipos QA siguen necesitando estructura, trazabilidad, puntos de aprobación y validación reproducible. QA FlowKit está 100% orientado al flujo QA — no es andamiaje de aplicaciones ni prompts genéricos de código.

1

El problema

Los prompts ad hoc producen Gherkin inconsistente, enlaces RF perdidos y CI sin contrato claro de qué significa “terminado” en QA.

2

El enfoque

Un arnés QA en el repositorio: fases, aprobaciones explícitas y validadores deterministas — no solo disciplina de prompt.

3

Para flujos QA

Desde la ingesta de requisitos hasta Gherkin, matriz de trazabilidad, plan de automatización y evidencia de release — cada paso tiene salidas definidas.

4

Límites claros

Sin modelo de IA propio, sin telemetría, sin escrituras externas silenciosas. Los artefactos permanecen locales y auditables en el repositorio.

Sin arnés de QA

  • Prompts puntuales sin orden de fases
  • Archivos .feature inconsistentes y tags faltantes
  • RF y criterios de aceptación perdidos entre sesiones
  • CI sin puerta de calidad compartida para artefactos QA

Con QA FlowKit

  • /qa-help recomienda el siguiente paso del flujo de trabajo
  • validate-target ejecuta la puerta de calidad completa del repositorio
  • run start | next | check retoma el trabajo entre sesiones del agente
  • Planes de sincronización solo-propuesta (proposal-first) — sin escrituras silenciosas en gestión de pruebas

Control desde el repositorio

De requisitos a evidencia de release

La IA razona y edita archivos. QA FlowKit controla el orden de fases, las salidas requeridas, las aprobaciones y las comprobaciones de éxito o fallo para que el equipo no dependa solo de la disciplina del prompt.

Paso 1 Requisito Ingesta e ID RF
→
Pasos 2–3 Diseño de pruebas Cobertura y plan de sincronización
→
Paso 4 Gherkin Archivos .feature
→
Paso 6 Trazabilidad Matriz RF → prueba
→
Pasos 7–8 Automatización Viabilidad y especificaciones
→
Paso 9 Release gate Evidencia lista para PR

Agente IA

Razona sobre requisitos, redacta Gherkin, propone planes de sincronización y automatización — edita archivos en el repositorio.

Arnés QA FlowKit

Valida salidas, bloquea fases inválidas, registra aprobaciones y mantiene estado resumible en .qa-ai/state/.

Las puertas de control clave incluyen confirmación del ID RF oficial, sincronización de gestión de pruebas en modo solo-propuesta (proposal-first) y validación determinista de Gherkin antes de trazabilidad y decisiones de release.

Al instalar QA FlowKit eliges cuánto del recorrido QA quieres que guíe. En ambos casos las pruebas, la trazabilidad y los validadores quedan en tu repositorio.

Quick — Equipos de QA manual: requisitos → Gherkin → matriz de trazabilidad Standard — Flujo completo: diseño de pruebas, plan de automatización y salidas para PR

Qué instala

Un arnés QA portable para repositorios de QA

QA FlowKit añade la carpeta del framework, configuración del repositorio objetivo, artefactos generados, archivos Gherkin y adaptadores opcionales para agentes dentro del repositorio bajo prueba.

Diseño trazable

Valida enlaces RF, IDs duplicados, obligaciones de cobertura y bloques de criterios de aceptación.

Validadores deterministas

Comprueba idioma Gherkin, tags requeridos, planes de sincronización, release gates y artefactos QA generados.

Flujo a tu medida

Empieza ligero para QA manual o usa el recorrido completo si vas a automatizar. Equipos con requisitos de auditoría pueden añadir después un checklist formal de release opcional.

Arnés resumible

Estado persistente de ejecución, registro de eventos y run status entre sesiones del agente.

Límites de seguridad

Mantiene las salidas locales, rechaza rutas inseguras, escanea contenido no fiable y evita escrituras externas en el MVP.

Superficie de comandos

Comandos CLI y de agente

Ejecuta la configuración inicial y la validación desde la terminal. Impulsa el flujo QA desde tu herramienta de IA con comandos slash generados.

En tu agente IA

Comandos slash generados en .claude/commands/ o .opencode/commands/ tras el init. Cada tarjeta enlaza a la definición del comando en el framework.

/qa-help

Guía contextual — qué hacer ahora en el flujo QA.
/qa-init

Inicialización guiada de QA FlowKit dentro de la sesión del agente.
/qa-config

Importar o exportar perfiles reutilizables de qa-ai.config.yaml.
/qa-full-flow

Ejecutar el flujo completo guiado de QA FlowKit de principio a fin.
/qa-add-tests

Añadir pruebas QA para un requisito (RF) nuevo.
/qa-update-tests

Revisar y aplicar actualizaciones aprobadas a pruebas existentes tras cambios en el RF.
/qa-automation-plan

Clasificar archivos .feature existentes y planificar el backlog de automatización.
/qa-coverage

Analizar cobertura funcional entre RFs, pruebas manuales y automatizadas.
/qa-impact

Proponer pruebas afectadas a partir de una rama, commit, PR o referencia de cambio.
/qa-quality

Evaluar la calidad Gherkin de un RF o ruta de features.
/qa-status

Resumir configuración, artefactos, salud de features y siguientes pasos recomendados.
/qa-doctor

Comprobaciones de salud del framework y del repositorio objetivo.
/qa-clean

Vista previa o ejecución de limpieza basada en manifiesto de archivos generados.
/qa-validate-features

Validar archivos Gherkin de diseño QA contra las reglas del framework.
/qa-validate-karate-features

Validar features Karate ejecutables contra las reglas del framework.
/qa-enable-enterprise

Opcional: checklist formal de release y validación más estricta para equipos con auditoría.
/qa-gate

Registrar una decisión documentada de go/no-go al usar el checklist de release opcional.

En tu terminal

npx qa-flowkit init

Instala .qa-ai/, genera la configuración, carpetas y adaptadores de agente seleccionados.

npx qa-flowkit doctor

Comprobación de estado de la instalación del framework y la configuración del repositorio objetivo.

npx qa-flowkit help

Recomienda el siguiente paso del flujo QA según los artefactos actuales.

npx qa-flowkit run start | next | check

Arnés resumible con validación por fase y puertas de aprobación.

npx qa-flowkit validate-target

Ejecuta la puerta de calidad completa del repositorio objetivo (doctor estricto + validadores).

npx qa-flowkit export-report

Exporta casos de prueba alineados con Gherkin a Cucumber JSON, Allure o JUnit XML.
